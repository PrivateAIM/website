What is federated analysis?

A short introduction to analyzing medical data without collecting it centrally

Federated analysis means analyzing data that is spread across several institutions without bringing it together in one place. Instead of copying patient data into a central database, the analysis is sent to each institution, runs there next to the local data, and only the results come back. Combined, these results answer the same research question as a central analysis, with the same or very similar results.

Why not collect the data centrally?

Many research questions, from rare diseases to training reliable AI models, need data from more patients than a single hospital has. Collecting this data centrally raises legal, organizational and security hurdles: health data is especially protected, every transfer has to be justified, and a central database is an attractive target. Federated analysis reduces these hurdles because the data never has to leave the hospital.

The idea: bring the analysis to the data

A researcher writes the analysis once. Each participating hospital reviews it, runs it on its own data and returns only an intermediate result, for example a count or a model update. An aggregator combines these intermediate results into the final result for the researcher.

Federated analysis and federated learning

Federated analysis

Statistics such as counts, means or regression models are computed at each site and combined once. Example: how many patients across all sites have a certain diagnosis?

Federated learning

A machine learning model is trained over several rounds. In each round the sites train on their local data and share only the updated model parameters, which are combined into a better global model.

What is shared, and what is not

Travels between sites

  • The analysis code, after it has been reviewed
  • Intermediate and aggregated results, such as counts or model parameters

Stays at each site

  • Patient-level data
  • Direct access to the local databases

Federated does not automatically mean anonymous

Aggregated results can still reveal information about individuals, for example when a group is very small. Federated analysis is therefore combined with further safeguards: each site reviews the code and its expected results before it runs, differential privacy adds calibrated noise to results, and homomorphic encryption lets sites combine values without seeing each other’s contributions.

Federated analysis in practice: FLAME

FLAME (Federated Learning and Analysis in Medicine) is the platform developed by PrivateAIM for federated analysis and federated learning at German university hospitals within the Medical Informatics Initiative (MII). It is open source and in productive use.
