FLAME

Federated Learning and Analysis in Medicine: the platform developed by PrivateAIM

FLAME is in productive use.

FLAME lets researchers analyze medical data from several institutions without the data ever leaving them. Instead of collecting data centrally, FLAME sends the analysis code to the data. Only aggregated results are returned.

FLAME (Federated Learning and Analysis in Medicine) is developed by PrivateAIM, a consortium of the German Medical Informatics Initiative (MII) funded by the BMFTR. It is not related to other software projects named Flame.

How FLAME works

FLAME consists of two parts: one central Hub and one Node at every participating site. The Hub coordinates, the Nodes compute.

  1. 1Every participating site runs a Node next to its own data. Patient data is never transferred to the Hub or to other sites.
  2. 2Every site decides whether it takes part in a project, reviews the analysis code before it runs, and starts the execution itself.
  3. 3The analysis runs at each site. The results of the sites are combined by an aggregator, and only this combined result is made available to the researcher.
  4. 4For iterative methods such as federated learning, this repeats over several rounds.

Safeguards

  • An analysis is only built and executed after every participating node has approved its code.
  • Every analysis runs in its own container without internet access.
  • All connections use TLS. Messages and intermediate results exchanged between nodes are additionally encrypted end to end, so the Hub cannot read them.
  • The Hub never has access to patient data.
  • Analyses can use privacy-enhancing techniques such as local differential privacy (currently for a single numeric result).
  • Users, roles and permissions are managed per organization. Starting an analysis and configuring data stores is reserved for the staff of the site.

Limits

Aggregation alone does not guarantee anonymity. FLAME does not automatically enforce minimum cohort sizes, k-anonymity thresholds or other output checks, so whether the returned results are appropriate is assessed during the review of each analysis.

Who is FLAME for?

Researchers

Write an analysis, test it locally with the FLAME SDK and run it across several sites. You only ever receive aggregated results.

Run your first analysis →

Data integration centres and sites

Each site runs a FLAME Node in its own Kubernetes cluster. The Node only needs outbound HTTPS, with no inbound access from the internet. Analyses can query data in FHIR format, such as the MII core dataset.

Install a Node →

Data protection officers

Every site reviews and approves each analysis before it runs. Analyses run in isolated containers, patient data stays on site, and only aggregated results are returned. See also the limits above.
