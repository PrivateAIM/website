FLAME

Federated Learning and Analysis in Medicine: die von PrivateAIM entwickelte Plattform

FLAME ist im produktiven Einsatz.

Mit FLAME können Forschende medizinische Daten mehrerer Einrichtungen analysieren, ohne dass die Daten diese jemals verlassen. Statt Daten zentral zu sammeln, bringt FLAME den Analysecode zu den Daten. Zurückgegeben werden nur aggregierte Ergebnisse.

FLAME (Federated Learning and Analysis in Medicine) wird von PrivateAIM entwickelt, einem vom BMFTR geförderten Konsortium der Medizininformatik-Initiative (MII). Mit anderen Softwareprojekten namens Flame hat es nichts zu tun.

Für wen ist FLAME?Neu bei föderierter Analyse?Eine kurze Einführung: wie Analysen ohne zentrale Datensammlung funktionieren und wo ihre Grenzen liegen.

So funktioniert FLAME

FLAME besteht aus zwei Teilen: einem zentralen Hub und einem Node an jedem teilnehmenden Standort. Der Hub koordiniert, die Nodes rechnen.

  1. 1Jeder teilnehmende Standort betreibt einen Node direkt bei seinen eigenen Daten. Patientendaten werden nie an den Hub oder an andere Standorte übertragen.
  2. 2Jeder Standort entscheidet selbst, ob er an einem Projekt teilnimmt, prüft den Analysecode vor der Ausführung und startet die Ausführung selbst.
  3. 3Die Analyse läuft an jedem Standort. Ein Aggregator führt die Ergebnisse der Standorte zusammen, und nur dieses Gesamtergebnis wird den Forschenden bereitgestellt.
  4. 4Bei iterativen Verfahren wie föderiertem Lernen wiederholt sich das über mehrere Runden.

Schutzmaßnahmen

  • Eine Analyse wird erst gebaut und ausgeführt, wenn alle teilnehmenden Nodes ihren Code genehmigt haben.
  • Jede Analyse läuft in einem eigenen Container ohne Internetzugang.
  • Alle Verbindungen nutzen TLS. Nachrichten und Zwischenergebnisse zwischen den Nodes sind zusätzlich Ende-zu-Ende-verschlüsselt, sodass der Hub sie nicht lesen kann.
  • Der Hub hat nie Zugriff auf Patientendaten.
  • Analysen können datenschutzfördernde Verfahren wie lokale Differential Privacy nutzen (derzeit für ein einzelnes numerisches Ergebnis).
  • Nutzende, Rollen und Berechtigungen werden je Organisation verwaltet. Das Starten von Analysen und das Einrichten von Datenquellen ist dem Personal des Standorts vorbehalten.

Grenzen

Aggregation allein garantiert keine Anonymität. FLAME erzwingt nicht automatisch Mindestfallzahlen, k-Anonymitäts-Schwellen oder andere Ausgabeprüfungen. Ob die zurückgegebenen Ergebnisse angemessen sind, wird deshalb bei der Prüfung jeder Analyse bewertet.

Für wen ist FLAME?

Forschende

Schreiben Sie eine Analyse, testen Sie sie lokal mit dem FLAME-SDK und führen Sie sie an mehreren Standorten aus. Sie erhalten ausschließlich aggregierte Ergebnisse.

Datenintegrationszentren und Standorte

Jeder Standort betreibt einen FLAME Node in einem eigenen Kubernetes-Cluster. Der Node benötigt nur ausgehendes HTTPS, ohne eingehenden Zugriff aus dem Internet. Analysen können Daten im FHIR-Format abfragen, etwa den MII-Kerndatensatz.

Node installieren (Englisch) →

Datenschutzbeauftragte

Jeder Standort prüft und genehmigt jede Analyse, bevor sie läuft. Analysen laufen in isolierten Containern, Patientendaten bleiben am Standort, und nur aggregierte Ergebnisse werden zurückgegeben. Beachten Sie auch die Grenzen oben.

Patientinnen, Patienten und Öffentlichkeit

Mit FLAME bleiben Ihre Daten in Ihrer Klinik. Forschende schicken ihre Analyse zu den Daten, statt die Daten zentral zu sammeln.
